# 문서 작성 규칙

red-wiki 의 모든 문서와 스킬이 이 규칙을 따른다. 문서를 쓰기 전과 고친 뒤에 이 목록으로 검토한다.
사람이 읽는 안내는 `docs/ops/` 에 있다 — 이 파일은 LLM 이 따르는 규칙이다.

## 1. 규칙만 쓴다

문서에는 **무엇을 하는가**만 적는다. 그 규칙을 고른 이유, 버린 대안, 이전 구조와의 차이는 적지 않는다. 경위가 필요하면 커밋 메시지에 남긴다.

- 쓰지 않는다 — `## 왜 목업을 _sources/ 에 두지 않나`, `이전 설계는 … 없앴습니다`

## 2. 결론부터 쓴다

절은 결론으로 시작한다. 배경·경위·조건을 앞에 두지 않는다.

- **쓴다** — "화면정의서의 저장 폴더는 `system:` 이 정합니다."
- 쓰지 않는다 — "화면이 늘면서 평평한 폴더로는 찾기 어려워졌기 때문에 …"

## 3. 문체는 문서마다 하나

| 대상                                        | 문체     |
| ------------------------------------------- | -------- |
| 사람이 읽는 문서 (`docs/`)                  | 합니다체 |
| LLM 이 읽는 파일 (`CLAUDE.md` · `.claude/`) | 한다체   |

한 문서 안에서 섞지 않는다. 표·목록 안은 개조식으로 통일한다.

## 4. 사람을 부르지 않는다

1인칭(우리·저희)과 독자 호명(당신·여러분)을 쓰지 않는다. 해명과 반박도 쓰지 않는다.

- **쓴다** — "동작은 아직 정해지지 않았습니다."
- 쓰지 않는다 — "지어내지 않고 비워 뒀습니다."

## 5. 현재시제로 쓴다

"~하게 됩니다", "~할 것입니다" 를 쓰지 않는다.

## 6. 시점 표현을 쓰지 않는다

**현재 · 새로운 · 최근 · 곧 · 이제 · 향후 · 기존** 을 본문에 쓰지 않는다. 문서는 반드시 낡고, 이 단어들이 낡는 속도를 앞당긴다. 날짜가 필요하면 frontmatter 에 적는다.

## 7. 형태를 내용에 맞춘다

| 내용                    | 형태        |
| ----------------------- | ----------- |
| 항목마다 속성이 셋 이상 | 표          |
| 순서가 있는 절차        | 번호 목록   |
| 순서 없는 나열          | 글머리 목록 |
| 그 외                   | 짧은 문장   |

항목이 하나뿐인 목록은 만들지 않는다. 표 앞에는 그 표가 무엇인지 밝히는 문장을 한 줄 둔다.

## 8. 같은 사실을 두 번 쓰지 않는다

한 곳에 두고 나머지는 링크한다. 두 문서에 같은 내용이 있으면 한쪽을 링크로 바꾼다.

## 9. 미완성은 `❓확인 필요` 하나로

모르는 것을 그럴듯한 문장으로 채우지 않는다. 표기는 둘뿐이다 — 본문은 `❓확인 필요: <무엇을 물어야 하나>`, 표 셀은 `❓`. 미결 질문을 본문에 나열하거나 왜 비었는지 설명하지 않는다.

## 10. 변경 이력은 본문에 쓰지 않는다

**이력은 `docs/product/` 문서만 쌓는다.** `ops/` 는 git log 로 충분하고, `wiki/` 는 원본에서 다시 만들어지는 층이라 이력이 의미가 없다.

짝 파일 `<문서>.history.yaml` 에 쌓고 앱이 본문 아래에 이어 그린다. 짝 파일은 문서 **옆**에 둔다 — 이력이 붙어도 문서를 옮기지 않는다. 사람은 앱의 편집 폼 하단 `Change log` 에서 남기고, AI 는 그 짝 파일을 직접 고친다.

## 11. 번역투와 군더더기를 걷어낸다

- `~적`, 불필요한 `~의`, `~되어진다`, `~에 대하여` 를 쓰지 않는다.
- 볼드는 한 절에 한두 곳까지. 수사의문문을 쓰지 않는다.

## 12. 스킬은 명령형으로 쓴다

`.claude/skills/<이름>/SKILL.md` 는 LLM 이 읽는 지시문이다.

- `description` 은 3인칭으로 **무엇을 하는지와 언제 쓰는지**를 적는다. "…한다. 사용자가 '…' 라고 할 때 사용한다."
- 본문은 명령형이다. 절 제목에 판단·강조를 넣지 않는다(`4. 지어내지 않는다 (가장 중요)` 가 아니라 `4. 원천에 없는 내용`).
- 본문 500줄을 넘기지 않는다.

## 13. 고친 뒤 확인한다

**명령을 치지 않는다.** 카탈로그(`index.md`) 재생성과 `title`·`registry.yaml` 경로 검사는 **앱이 문서를 저장할 때 스스로** 한다.

AI 가 파일을 직접 고쳤을 때는 그 검사가 돌지 않는다. 아래 셋을 눈으로 본다.

- frontmatter 에 `title` 이 있는가
- `registry.yaml` 이 가리키는 경로가 실제로 있는가
