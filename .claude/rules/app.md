# 앱이 하는 일

**이 저장소에는 코드가 없다.** 뷰어·스크립트·명령은 전부 **Red Wiki 데스크탑 앱**(`offen-red/red-wiki-desktop`) 안에 있다. 여기는 문서만 담는다.

그래서 `docs/ops/` 는 **이 저장소의 코드**를 설명하는 문서가 아니라 **앱을 쓰는 법**을 설명하는 문서다. 고칠 때 기준이 갈린다.

| 이런 요청                                | 어디서                                                          |
| ---------------------------------------- | --------------------------------------------------------------- |
| "버튼이 안 먹는다", "이 기능 추가해 줘"  | 앱 저장소. 여기서 고칠 것이 없다                                |
| "앱이 이렇게 동작한다고 문서에 적어 줘"  | `docs/ops/` — 단, **버튼 글자를 앱 코드에서 확인하고** 인용한다 |
| "npm 명령이 안 된다"                     | 그런 명령은 없다. 아래를 읽는다                                 |

## npm 도, 스크립트도 없다

카탈로그 갱신(`index.md`)·검사·노션 동기화·변경 이력은 **앱이 자기 안에 든 도구로** 한다. 사람이 명령을 치지 않는다.

`npm run index` · `npm run dev` 같은 문장을 문서에 새로 쓰지 않는다. 옛 문서에서 발견하면 앱 동작으로 고친다.

## 사람이 앱에서 하는 일

AI 는 이 흐름을 알고 있어야 같은 일을 두 번 시키지 않는다.

| 화면                             | 무엇을                                                                                                                          |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| **새로 만들기** (`/new`)         | 만들기 입구는 **하나**다. 유형 탭에서 `screen` 을 고르면 전용 폼(`/new/screen`)으로 넘어간다                                     |
| **화면 올리기** (`/new/screen`)  | 화면을 **처음 올릴 때.** System·Screen ID·Title·Spec·Mockup 을 받고 저장 경로·작성자는 자동                                      |
| 화면정의서의 **[버전 업데이트]** | **화면 작업의 주 동작.** Claude Design 에서 고쳐 온 파일로 갈아끼우고 변경 이력을 남긴다. 파일 없이 이력만 남길 수도 있다        |
| **스킬 등록** (`/new/skill`)     | `SKILL.md` 를 받아 `.claude/skills/<이름>/` 에 둔다. **본문은 폼에서 쓰지 않는다** — 그 파일이 곧 Claude Code 가 실행하는 절차다 |
| **화면 현황** (`/screens`)       | 전 화면을 시스템 폴더별 표로. 상태·남은 `❓`·목업 유무·최근 수정자를 **문서에서 계산해** 보여준다                                |
| **원천 뷰** (`/sources`)         | 문서에 붙은 이미지와 노션 미러. 미러 동기화도 여기서 한다                                                                       |
| **저장소** (헤더)                | 어느 위키를 이 컴퓨터에서 볼지. 목록은 GitHub 권한이 정한다                                                                     |
| 문서의 **[삭제]**                | 파일을 지운다. 사이드바는 폴더 구조를 따르므로 저절로 사라진다. 화면은 폴더째                                                   |

**앱은 정의서 내용을 쓰거나 고치지 않는다.** 목업과 정의서는 Claude Design 에서 만들고 고치고, 앱은 받아서 보관한다. 정의서를 채워 달라는 요청은 그 세션에서 쓰라고 답한다(`docs/ops/authoring/screen-spec.md`).

## 고친 것은 검토 요청으로 나간다

앱에서 저장하면 이 컴퓨터에 바로 쓰이고, 상단바의 **[검토 요청]** 을 누르면 새 브랜치와 PR 이 열린다. 병합·반려는 GitHub 에서 한다. 여기서 `git push` 를 직접 하지 않는다.
