# /change-propagation — 변경 전파

인자로 고친 파일을 받는다. 인자가 없으면 `git status` 와 `git diff` 로 무엇이 바뀌었는지 찾아 확인받는다.

## 1. 무엇이 바뀌었나

`git diff` 로 실제 변경된 사실을 추린다. 전파 대상은 다음 여섯이다.

- 기능 · 요구사항의 추가 · 삭제 · 변경
- 용어 · 명칭의 변경
- 경로 변경 (파일 이동 · 이름 변경)
- 시스템 간 경계 · 연계 변경
- 범위 결정 (무엇을 하지 않기로 했는지)
- **앱 동작 변경** — 화면 · 버튼 · 동작. 코드는 앱 저장소에 있고 여기서는 `docs/ops/` 만 맞춘다

오탈자와 문장 다듬기는 전파하지 않는다. 코드도 내부 리팩터링은 전파하지 않는다 — **사람이 보는 동작이 바뀌었을 때만**이다.

## 2. 영향 범위를 찾는다

| 찾을 곳                               | 방법                                |
| ------------------------------------- | ----------------------------------- |
| 그 문서를 `related:` 로 가리키는 문서 | 파일 경로로 grep                    |
| 같은 용어 · 기능명을 쓰는 문서        | 바뀐 용어로 `docs/` 전체 grep       |
| `registry.yaml`                       | 경로 · 도메인 · 원천 매핑           |
| (사이드바)                            | 손댈 것 없음 — 폴더 구조와 frontmatter `title` 이 그대로 반영된다 |
| 상위 `overview.md`                    | 요약 · 표에 그 내용이 실린 경우     |
| **`docs/ops/**`**                     | 앱 동작이 바뀌었을 때. 아래         |


### 앱 동작 → 그것을 설명하는 문서

`docs/ops/` 는 **Red Wiki 데스크탑 앱**을 쓰는 법을 설명한다. 코드는 이 저장소에 없다
(`offen-red/red-wiki-desktop`). 그래서 여기서 하는 일은 **앱이 바뀌었다는 소식을 받았을 때**
그 문서를 맞추는 것뿐이다.

| 앱에서 바뀐 것                   | 확인할 문서                         |
| -------------------------------- | ----------------------------------- |
| 명령·검사·알림                   | `docs/ops/tooling/commands.md`      |
| 노션 미러 동작·frontmatter       | `docs/ops/tooling/notion-mirror.md` |
| 화면 올리기·버전 업데이트·보기   | `docs/ops/tooling/screens.md`       |
| 문서 유형·frontmatter 항목       | `docs/ops/tooling/templates.md`     |
| 사이드바·폴더 규칙·저장소 관리   | `docs/ops/overview.md`              |

**문서에 UI 를 인용할 때는 버튼·탭·필드의 글자를 앱 코드에서 확인한다.** 기억으로 쓰지 않는다.
확인할 길이 없으면 지어내지 말고 `❓확인 필요` 로 남긴다.

## 3. 먼저 보여준다

고치기 전에 다음 형식으로 목록을 제시한다.

```
바뀐 사실: <한 줄>
전파 대상:
  docs/product/... — <무엇을 어떻게>
  docs/ops/...     — <코드가 바뀐 경우>
  registry.yaml    — <무엇을>
전파 안 하는 것:
  docs/... — <왜 아닌지>
```

전파하지 않는 대상도 함께 적는다. 빠뜨린 것과 의도적으로 제외한 것을 구분할 수 있어야 한다.

## 4. 고친다

- 사실을 복제하지 않는다. 두 문서가 같은 내용을 담고 있으면 한쪽을 링크로 바꿀 것을 제안한다.
- **UI 를 인용할 때는 버튼·탭·필드의 글자를 코드에서 직접 확인한다.** 기억이나 다른 문서에 적힌 이름을 옮기지 않는다 — 코드에 없는 버튼을 안내하는 문장이 실제로 여러 건 쌓였다.
- 헤딩 구조를 유지하고 해당 절만 고친다.
- 어느 쪽이 맞는지 모르는 지점은 고치지 않고 `❓확인 필요:` 로 남긴다.
- 변경 이력 표가 이미 있는 문서에만 행을 추가한다. 없는 문서에 새로 만들지 않는다. "왜" 열을 채운다.
- 문체는 `.claude/writing-style.md` 를 따른다.

## 5. 마무리

`CLAUDE.md` 6절의 공통 마무리를 따른다. 커밋 메시지 첫 줄은 다음 형식으로 쓴다.

```
docs: <바뀐 사실> → <전파된 문서 수>건 반영
```

보고에는 고친 문서, 전파하지 않은 문서와 이유, `❓확인 필요` 지점을 포함한다.
