# /draft — 문서를 제안한다

**파일을 고치지 않는다.** 도구는 `Read`·`Glob`·`Grep` 뿐이고 그걸로 충분하다. 이 스킬의 결과물은 파일이 아니라 **제안 블록**이고, 뷰어가 그걸 검토 카드로 그린다. 사람이 [폼에서 열기] 를 눌러야 문서가 생긴다.

그래서 여기서 할 일은 하나다 — **바로 저장해도 될 만큼 완성된 것을 낸다.**

## 절차

### 1. 어디에 들어갈지 먼저 정한다

`index.md` → `registry.yaml` → 해당 폴더 순으로 본다. **같은 것을 말하는 문서가 이미 있으면 새로 만들지 않는다.** 그 문서를 고치자고 제안한다. 위키에서 가장 흔한 사고는 같은 사실이 두 문서에 갈라져 사는 것이다.

존과 폴더는 `.claude/rules/authoring.md` 가 정한다. 애매하면 묻는다.

### 2. 근거를 모은다

`/ask` 와 같다. **문서에 없는 것은 쓰지 않는다.** 제품 문서가 비어 있어 채울 것이 없으면, 지어내지 말고 뼈대만 내고 빈 칸에 `❓확인 필요: ...` 를 남긴다.

레포 코드나 설정을 설명하는 문서라면 **코드를 읽고 쓴다.** 버튼 이름·명령 이름은 기억으로 쓰지 않는다.

### 3. 고칠 문서는 반드시 먼저 읽는다

제안은 **전체 본문**이다. 읽지 않고 전체를 내면 기존 내용을 지운다. 안 읽었으면 제안하지 않는다.

### 4. 제안 블록으로 낸다

**문법·거절 조건·`generated:` 표시는 `.claude/rules/proposal-block.md` 가 정한다. 처음 블록을 내기 전에 그 파일을 읽는다.** 여기 다시 적지 않는다 — 두 곳에 두면 반드시 어긋난다.

파일 하나에 블록 하나. 블록 밖에 같은 본문을 또 적지 않고, 블록 **위**에 무엇을 왜 이렇게 썼는지 두세 문장만 적는다.

### 5. 제안 뒤에 한 줄

무엇을 확인해야 하는지 짚는다. `❓확인 필요` 를 남겼으면 어디에 남겼는지 전부 적는다.

## 제안하지 않는 것

| | 왜 |
| --- | --- |
| `docs/_sources/` | 사람이 던지는 원천 층이다. 손대지 않는다 |
| `mirror: notion` 이 붙은 문서 | 노션이 원본이라 여기서 고치면 다음 `pull:notion` 에 덮인다. 노션에서 고치라고 답한다 |
| 화면정의서(`screen`) | 목업과 정의서는 Claude Design 세션에서 만든다. 여기서는 안 만든다 |
| `.claude/` · 코드 파일 | 이 스킬은 `docs/` 만 제안한다 |

## 여러 개를 고쳐야 할 때

**세 개까지는 그냥 낸다.** 그보다 많아지면 블록을 쏟기 전에 **목록을 먼저 보여주고 묻는다** — 카드 열 장이 한꺼번에 뜨면 아무도 검토하지 않고 전부 누른다.

## 예시

```
사용자: docs 에 문서 추가하고 싶은데 guide 에 Kiwi AI 설명 써줄 수 있어?

읽음: index.md, registry.yaml, docs/ops/tooling/commands.md, src/components/workbench/AskPanel.tsx

답: ops 존에 넣었습니다 — 뷰어를 어떻게 굴리는지에 대한 문서라 product 가 아닙니다.
    동작은 코드에서 확인해 적었고, 과금은 문서에 근거가 없어 ❓로 남겼습니다.

    ```red-doc
    @path docs/ops/tooling/kiwi-ai.md
    ---
    title: Kiwi AI
    type: guide
    status: 작성중
    owner: 수빈
    ---
    ...
    ```

    ❓확인 필요는 "과금" 절 한 곳입니다.
```
